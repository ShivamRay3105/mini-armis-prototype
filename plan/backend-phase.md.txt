# Phase 1: Asset Service (Week 1–2)

## Responsibilities (DO NOT OVERLOAD IT)

Asset Service is **state**, not intelligence.

### It should:

* Store assets (PLCs, HMIs, RTUs)
* Track:

  * protocol
  * zone
  * last_seen
  * current risk_score
  * status (active / maintenance / acknowledged)

### It should NOT:

* Calculate risk
* Generate alerts
* Talk to Kafka (yet)

---

## Minimal API you must implement

```http
POST /assets
GET  /assets
GET  /assets/{id}
PATCH /assets/{id}/status
PATCH /assets/{id}/risk
```

### Example asset payload

```json
{
  "deviceType": "PLC",
  "protocol": "MODBUS",
  "zone": "OT_ZONE_1",
  "ipAddress": "10.0.0.12"
}
```

### Stored internally

```text
asset_id
device_type
protocol
zone
risk_score (int)
last_seen
status
```

---

## Roles & permissions (IMPORTANT)

| Role             | Permission             |
| ---------------- | ---------------------- |
| Security Analyst | READ assets, READ risk |
| OT Admin         | CREATE / UPDATE assets |
| System Admin     | ALL + health           |

Enforce this **at the gateway**, not inside service logic.

---

## Event Ingestion API

```http
POST /events/simulate
```

```json
{
  "assetId": "123",
  "eventType": "CONNECTION_ATTEMPT",
  "protocol": "MODBUS",
  "zone": "OT_ZONE_1"
}
```

### What this service does

* Validate asset exists
* Add timestamp
* Publish to Kafka → `asset-events`

No DB required initially.

# Phase 4: Risk Engine (Week 4)

This is NOT AI.
This is **deterministic rules**.

Example rule set:

```text
IF protocol == MODBUS AND zone == OT → +40
IF deviceType == PLC → +30
IF multiple events in 5 mins → +20
```

### Output

```json
{
  "assetId": "123",
  "riskScore": 85,
  "reason": "Unsafe protocol in OT zone"
}
```

* Publish to `risk-events`
* Call Asset Service → update risk_score
